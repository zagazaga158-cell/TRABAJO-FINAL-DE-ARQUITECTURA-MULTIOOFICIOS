# Restricciones — TrabajaYa Perú (`conectaoficios`)

Identificar las **restricciones técnicas, operativas y regulatorias** que condicionan las decisiones de diseño y arquitectura del sistema:

| ID | Restricción | Descripción detallada en el proyecto |
| :--- | :--- | :--- |
| **RC01** | **Aplicación Web SPA Responsive (React 19 + TypeScript)** | El frontend debe ejecutarse como una Single Page Application accesible en escritorio y dispositivos móviles (`360px` a `1920px+`), construida con **React 19**, **TypeScript**, **Tailwind CSS v4** y **Vite 8** con carga diferida (`React.lazy` + `manualChunks`). |
| **RC02** | **Backend Node.js ESM + Express + WebSocket** | El servidor (`server.ts`) debe operar sobre **Node.js ESM (`type: "module"`)**, **Express 4** (límite de payload JSON `2mb`) y **`ws`** en `/ws/chat`, sirviendo tanto los endpoints REST/WS como el host de la SPA (`vite.middlewares` en desarrollo y `dist/` en producción). |
| **RC03** | **API REST JSON y Mensajería en Tiempo Real** | La comunicación cliente-servidor debe seguir contratos REST JSON (`/api/health`, `/api/cache/stats`, `/api/payments/culqi/*`, `/api/chat/*`, `/api/notifications/dispatch-order`) complementados por eventos WebSocket `/ws/chat` con idempotencia por `messageId`. |
| **RC04** | **Pasarela de Pago Nacional Culqi Perú (`PEN`)** | Los cobros de planes, imprevistos (`S/ 5.00`) y custodia Escrow deben integrarse con **Culqi Perú** (`Checkout v4` en navegador + `Charges API v2` en servidor) exclusivamente en **Soles Peruanos (`PEN`)**, monto mínimo `S/ 1.00` (`100` céntimos), sin almacenar jamás números ni CVV de tarjetas y manteniendo `CULQI_SECRET_KEY` solo en servidor. |
| **RC05** | **Integraciones de Notificación y Geolocalización** | El despacho de órdenes debe soportar **SMTP Nodemailer / Webhook** y **Meta WhatsApp Cloud API v20.0 / Webhook** con degradación elegante a cola local y enlaces manuales (`Gmail`, `mailto:`, `wa.me`), además de `navigator.geolocation` y enlaces de **Google Maps**. |
| **RC06** | **Marco Regulatorio y Contexto Peruano** | Cumplimiento de la **Ley N.º 29733** (privacidad del Expediente Legal de 5 Bloques), validación de documentos nacionales (`DNI` 8 dígitos, `CE`/`PASAPORTE` 6–15 chars, `RUC` 11 dígitos, prefijo `+51`), cálculo de **IGV 18%**, división política **Ubigeo Perú (25 regiones, 196 provincias, 1,878 distritos)** y acreditación **SENATI / SENCICO / CAPECO**. |
| **RC07** | **Control de Versiones, Base de Datos y CI/CD** | Código fuente y base de datos **PostgreSQL 16** versionados en Git (*Database-as-Code* en `database/`), con exclusión estricta de secretos (`.env*` en `.gitignore`) y pipelines automatizados en **GitHub Actions** (`.github/workflows/ci.yml` y `cd.yml`). |
| **RC08** | **Persistencia Dual (Autonomía Demostrativa + Producción)** | En modo demostrativo/local el sistema opera de forma autónoma con `localStorage` (`safeLocalStorageSet` + compresión de imágenes `mediaUpload.ts`) y `.data/*.json`, pero la arquitectura está diseñada y documentada para migrar limpiamente a **PostgreSQL 16 + PgBouncer + Redis 7 + Object Storage S3/R2**. |
