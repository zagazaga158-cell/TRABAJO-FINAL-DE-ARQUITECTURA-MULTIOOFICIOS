# Atributos de Calidad — TrabajaYa Perú (`conectaoficios`)

> **Estándar de Referencia:** ISO/IEC 25010 (SQuaRE).

| ID | Atributo de calidad | Escenario de calidad aplicado a TrabajaYa Perú | Evidencia / Mecanismo en el proyecto |
| :--- | :--- | :--- | :--- |
| **AC01** | **Rendimiento** | Las consultas de catálogo nacional (14 oficios y 1,878 distritos), configuración Culqi, transacciones y conversaciones deben responder con latencia mínima incluso bajo carga concurrente. | Caché `LruTtlCache` (`server/cache.ts`) con `ETag`/`304`, code splitting (`React.lazy` + `manualChunks`), índices compuestos + GIN FTS en PostgreSQL. Benchmark verificado: **`p95 = 48.03–54.69 ms`** y **`99.87%` Cache Hit**. |
| **AC02** | **Disponibilidad y Resiliencia** | La plataforma debe mantenerse operativa de forma continua para atender solicitudes normales y emergencias domésticas, tolerando fallas temporales de servicios externos. | Healthcheck `GET /api/health`, degradación elegante en Culqi (Sandbox), SMTP y WhatsApp (cola local + enlaces manuales), reconexión WS cada `2500ms`, fallback WS si falla POST de chat y Graceful Shutdown (`SIGTERM`). |
| **AC03** | **Escalabilidad** | El sistema debe escalar desde un despliegue inicial hasta tráfico masivo en las 25 regiones del Perú sin degradar latencia ni comprometer reservas de turnos. | Contenedores stateless (`Dockerfile`, `docker-compose.yml`), Nginx `least_conn` (`infra/nginx.conf`), Cloudflare CDN, PgBouncer (`pool_mode = transaction`), PostgreSQL Primary/Replicas + particionamiento mensual + Redis Pub/Sub y Locks. |
| **AC04** | **Seguridad y Privacidad** | Los datos personales, domicilios GPS, Expediente Legal de 5 Bloques (Ley N.º 29733), credenciales Culqi y mensajería deben protegerse contra accesos no autorizados. | `CULQI_SECRET_KEY` exclusiva de servidor, RBAC de 2 roles + Admin único (`uq_single_admin_only`), bloqueo `401` en chat a `GUEST`, privacidad `canViewIdentityMedia`, Rate Limiter L7 (`429`), cabeceras de seguridad y SSL Full Strict + WAF. |
| **AC05** | **Mantenibilidad y Testabilidad** | El código debe permanecer tipado, modular, gobernado por especificaciones SDD y verificable de forma automatizada en cada cambio. | Clean Architecture (`src/domain/businessRules.ts`, `server/cache.ts`), TypeScript estricto (`0` errores), `36/36` pruebas unitarias/integración (Vitest + Supertest), `6/6` E2E (Playwright) y CI/CD en GitHub Actions. |
| **AC06** | **Usabilidad y Portabilidad** | Interfaz intuitiva en español peruano (`es-PE`), responsive en móvil y escritorio, ejecutable de manera uniforme en Windows, Linux y Docker. | Design System responsive validado en `375×812` (`E2E-06`), diferenciador cromático `amber` (Usuario) vs. `sky` (Admin), 10 Heurísticas de Nielsen y ejecución reproducible vía Node.js ESM / Docker. |
| **AC07** | **Auditabilidad e Integridad Financiera** | Toda operación monetaria (`PEN`, garantía 10%, IGV 18%), transición Escrow y despacho de orden debe ser matemáticamente exacta y rastreable cronológicamente. | Redondeo estricto a 2 decimales, `historialEstados[]`, `.data/culqi-transactions.json`, `.data/dispatch-log.json`, idempotencia por `messageId` y columnas generadas + transacciones ACID en PostgreSQL. |
