# Drivers Arquitectónicos — TrabajaYa Perú (`conectaoficios`)

Los **drivers arquitectónicos** sintetizan los requisitos funcionales clave, atributos de calidad y restricciones que moldean la estructura del sistema:

| ID | Driver arquitectónico | Origen | ¿Por qué influye directamente en la arquitectura? |
| :--- | :--- | :--- | :--- |
| **DA01** | **Picos de demanda y cobertura nacional (25 regiones / 1,878 distritos)** | `AC03` – Escalabilidad; `RF02`, `RF06` | Determina el uso de code splitting en frontend (`React.lazy` + `manualChunks`), CDN en borde (Cloudflare PoP Lima), balanceo horizontal `least_conn` (Nginx), contenedores stateless (`Dockerfile`) y escalado de PostgreSQL con Read Replicas y PgBouncer. |
| **DA02** | **Baja latencia en catálogo, pagos y consultas frecuentes** | `AC01` – Rendimiento; `RF02`, `RF14` | Condiciona la implementación de caché multi-nivel (`server/cache.ts` LRU/TTL + `ETag 304` + invalidación por prefijo y puerto listo para Redis) y el diseño de índices compuestos parciales y GIN Full-Text Search en PostgreSQL. |
| **DA03** | **Privacidad del Expediente Legal (5 Bloques), RBAC estricto y custodia Culqi** | `AC04` – Seguridad; `RC04`, `RC06`, `RF01`, `RF04` | Impone la separación de secretos exclusivamente en servidor (`CULQI_SECRET_KEY`), el modelo RBAC de 2 roles con Administrador Único (`uq_single_admin_only` en SQL), bloqueo `401` a invitados en chat, privacidad `canViewIdentityMedia` y Rate Limiting L7 (`429`). |
| **DA04** | **Integración resiliente con proveedores externos (Culqi, SMTP, WhatsApp, GPS)** | `RC04`, `RC05`, `AC02` – Integraciones y Resiliencia | Exige encapsular cada proveedor detrás de adaptadores con **degradación elegante** (Culqi API v2 → Sandbox; SMTP → Webhook → Cola + Gmail/`mailto:`; Meta WhatsApp Cloud API → Webhook → Cola + `wa.me`) para que ningún fallo externo detenga la creación de órdenes. |
| **DA05** | **Comunicación en tiempo real e idempotencia en órdenes y chat** | `RC03`, `RF08`, `RF12`, `AC07` | Impone un servidor híbrido HTTP + WebSocket (`/ws/chat`) con deduplicación por `messageId`, reconexión automática (`2500ms`), fallback WS si falla POST y diseño de backplane **Redis Pub/Sub** para múltiples réplicas. |
| **DA06** | **Integridad transaccional Escrow y prevención de doble reserva de turnos** | `RF09`, `RF10`, `AC07` | Impone una **Máquina de Estados Finita Escrow** de 6 estados, cálculos centralizados en capa pura de dominio (`src/domain/businessRules.ts`) y bloqueo atómico transaccional (`sp_reservar_turno_atomico` con `SELECT ... FOR UPDATE` + Redis Locks). |
| **DA07** | **Mantenibilidad, evolución SDD y verificación continua** | `AC05`, `RC07` | Justifica adoptar **Monolito Modular + Clean Architecture + Spec-Driven Development (`docs/sdd/`)** respaldado por pirámide de pruebas (`36` Vitest/Supertest + `6` Playwright E2E + `k6`) y CI/CD en GitHub Actions. |
