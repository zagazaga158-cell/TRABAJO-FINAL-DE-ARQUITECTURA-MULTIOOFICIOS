# Decisiones Arquitectónicas (ADRs) — TrabajaYa Perú (`conectaoficios`)

| ID | Decisión arquitectónica | Driver relacionado | Justificación | Resultado concreto en el proyecto |
| :--- | :--- | :--- | :--- | :--- |
| **ADR-001** | **Monolito Modular Full-Stack en un único runtime Node.js** | `DA01`, `DA06`, `DA07` | Ofrece consistencia transaccional directa entre reservas, órdenes Escrow y despacho, baja latencia y despliegue simplificado (HTTP + WebSocket + SPA) sin la complejidad operativa prematura de microservicios. | Fronteras explícitas entre 9 módulos funcionales desplegados mediante `server.ts` y escalables horizontalmente en `docker-compose.yml` + `infra/nginx.conf`. |
| **ADR-002** | **Clean Architecture + Desarrollo Basado en Especificaciones (SDD)** | `DA06`, `DA07` | Aísla las invariantes de negocio (Escrow 10%, IGV 18%, validadores de documento, ranking de catálogo, privacidad Ley 29733 y máquina de estados) de React, Express y almacenamiento. | Capa pura `src/domain/businessRules.ts`, puerto `CacheStore` (`server/cache.ts`), suite normativa `docs/sdd/` y `36/36` pruebas unitarias/integración sin dependencias de navegador. |
| **ADR-003** | **RBAC estricto de 2 permisos (`USUARIO`, `ADMIN`) con Administrador Único (`ADM-001`)** | `DA03` | Evita proliferación de roles permitiendo que un mismo ciudadano opere como `CLIENTE_HOGAR`, `OFERTANTE_OFICIO` o `AMBOS` sin duplicar cuentas, mientras blinda el gobierno nacional en un único `ADMIN`. | Enforced en 3 capas: UI/Contexto (`ConectaContext.tsx`), hidratación auto-saneada y motor SQL (`uq_single_admin_only` en `database/01_schema.sql`). |
| **ADR-004** | **Pasarela Culqi Perú con modo dual (API v2 real + Sandbox automático)** | `DA03`, `DA04` | Protege `CULQI_SECRET_KEY` en el backend conforme a PCI-DSS y permite pruebas completas de extremo a extremo sin credenciales bancarias productivas, conmutando automáticamente al configurar `.env`. | `CulqiCheckoutModal.tsx` + `/api/payments/culqi/config`, `/charge` y `/transactions` auditados con campo `mode: 'live' | 'test' | 'sandbox'`. |
| **ADR-005** | **Caché Multi-Nivel con `LruTtlCache` + `ETag 304` + Puerto Redis** | `DA02`, `DA01` | Reduce I/O sobre disco/BD en lecturas repetidas sin servir datos obsoletos mediante invalidación inmediata en escrituras y prefijos, preparado para Redis 7 en clúster. | `server/cache.ts` (`X-Cache: HIT|MISS`, `304 Not Modified`, `/api/cache/stats`), alcanzando **`99.87%` de Cache Hit Ratio** y `3,891.9 RPS`. |
| **ADR-006** | **Despacho Automático Multicanal con Degradación Elegante e Idempotencia** | `DA04`, `DA05` | Garantiza entrega inmediata de cada solicitud al técnico incluso si SMTP o Meta WhatsApp API no están configurados o fallan temporalmente, evitando mensajes duplicados. | `POST /api/notifications/dispatch-order` (Chat WS instantáneo + SMTP/Webhook + WhatsApp Cloud API/Webhook + `.data/dispatch-log.json`) + `messageId` idempotente. |
| **ADR-007** | **Code Splitting Frontend (`React.lazy` + `manualChunks`) + Compresión de Medios Cliente** | `DA01`, `DA02` | Minimiza el peso de carga inicial en conexiones móviles del Perú, separa vendors inmutables para CDN y evita desbordar `localStorage` con fotos del expediente y galería. | `App.tsx`, `vite.config.ts` (`> 382 kB` diferidos fuera del bundle inicial, build `374–588 ms`) y `src/utils/mediaUpload.ts`. |
| **ADR-008** | **Persistencia Híbrida Demostrativa con Migración Directa a PostgreSQL 16 + PgBouncer** | `DA01`, `DA06`, `RC08` | Permite ejecutar la app localmente sin infraestructura externa, manteniendo un esquema SQL 3FN real listo para producción con índices, particionamiento y bloqueo `FOR UPDATE`. | `localStorage` (10 claves) + `.data/*.json` en local; `database/01_schema.sql`, `02_indexes_and_scalability.sql`, `03_seed_data.sql` e `infra/pgbouncer.ini` para producción. |
